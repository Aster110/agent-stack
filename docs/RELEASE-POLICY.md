# 一份源码与稳定发布

后续维护入口：`https://github.com/Aster110/agent-stack`。公开仓从清理过的源码快照开始；原仓保留私有历史。不要在公开版和私人版分别修同一个运行时。

同源指：所有角色从同一个 release 标签和 commit 构建；macOS/Linux 原生依赖可以不同，运行时源码与协议版本一致。地址、所有者、Codex 登录、角色、密钥、路径和数据库各自独立。

`bootstrap.sh` 在本地 `.release-info.json` 记录版本、commit 和源码哈希。用 `python3 scripts/source-version.py --verify` 检查安装后源码是否变化，并跨机比较 sourceHash。此命令只证明磁盘源码；仍需核实实际服务入口，不能把源码哈希当运行状态。

当前最新候选为 `v0.1.0-rc.2`，没有正式 stable。`main` 是开发分支。生产设备固定已验收版本，不自动 `git pull main`。不能为了版本号相同而覆盖正在工作的主脑。

稳定版完成判据：同一提交在 macOS/Linux 干净构建及回归通过；新电脑和独立服务器按 SOP 安装；真实微信派单到电脑，核验实际交付物和微信回复；验证重启、断网及恢复；至少 48 小时无丢任务、错误回程、重复模型执行、意外换会话或持续增长的孤儿进程。公开候选源码不以完成生产迁移为前提。

升级逐台记录源码 checkout、构建来源 commit、服务实际入口、PID/启动时间、配置 schema、Codex/Node 版本。目录 HEAD 不代表服务正在使用它。先清点未提交补丁、独立 release 目录、服务和运行任务；需要保留的修复先合回公开源码并回归。备份状态，逐台替换并真实收发验收，最后切主脑。

本次 runtime contract 为 6，旧二进制不得写新状态目录。保留独立旧状态才能回退；不能假定二进制降级等于状态可降级。新旧服务不得抢占同一微信账号或 mesh 席位。版本一致必须以运行进程和端到端结果为依据。
